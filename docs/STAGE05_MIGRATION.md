# Stage 05M — portable authenticated checkpoints
A logical plan hash binds the program, versioned checked-add semantics, stable postorder operands and output, excluding physical device identity and lane placement. A portable state uses the unified envelope with op portable-checkpoint, a logical hash, cursor, HMAC-SHA256 and completed value objects. Destination recompiles the plan, checks its capability grants and limits, validates the checkpoint and its MAC, then evaluates only the remaining suffix. Test instruments primitive calls: two on source and one on destination for ((2+3)+(4+5)); total three, not five.

Trust model: caller supplies a secret of at least 32 bytes shared by trusted source and destination; generate and distribute it securely outside this prototype. MAC authenticates state from a key holder, not correctness against a malicious key holder. No encryption, key management, anti-replay, remote communication, exactly-once semantics, process isolation, live GPU migration or side effects. Replaying an older valid checkpoint remains possible. The current stable postorder is a logical execution prefix; arbitrary reordered completed-node sets are deferred. Destination must fit the entire compiled plan even if only a small suffix remains. Physical scheduling is still simulated sequentially. Old replay checkpoints remain unchanged and incompatible. CI pending at submission. Run python -m unittest discover -s tests -v.
